# Self-hosted sync example

The complete source is in [`example/self-host-sync`](../../../../example/self-host-sync/readme.md): `plugin/` is a declarative Wasm plugin, `server/` is a single-user Go service, and `build-release.py` creates a companion Release ZIP. The plugin declares `uiNavigation`, `uiPage`, and protected `sshSync`. The host-owned secure flow reads login fields. Plugin code declares same-origin HTTP/HTTPS endpoints and sync actions but never receives Vault plaintext, the sync key, passwords, tokens, or exchange bytes. HTTP exposes passwords, tokens, and request metadata in transit.

From the repository root, run `PATH=<go-bin>:$PATH python3 example/self-host-sync/build-release.py`. This requires Go 1.23+, the locked Rust 1.97.1 toolchain, and its `wasm32-unknown-unknown` target. The script cross-builds six server binaries, exercises the real Wasm Plugin Host verifier and SDK `pack`/`check`, then creates separate server and plugin ZIPs. Building it does not install, authorize, accept on native desktop, or publish it.

Core owns the in-app automatic sync scheduler; plugin Wasm cannot run its own timer to request protected actions. Each run checks the package, instance, grant, configured URL, Vault, and baseline again. V5 three-way merge uses per-item update times; conflict and deletion policies are separate host-persisted settings that a Wasm request cannot escalate. Automatic writes pause for unknown change times, a new baseline, or unresolved restore. Startup checking is read-only. Host adapters export eight groups of non-secret preferences and apply them with per-group CAS. Collecting a snapshot does not invent a change time, so a two-device preference conflict without reliable times requires review. Core persists a pending intent before SSH/desktop restore; uncertain results require an explicit clear and a new manual sync. The server authenticates its separate service password, manages sessions and ETag/CAS, and stores Core ciphertext unchanged.

Core derives a stable data owner from the plugin ID for new remote exchanges. For an existing exchange, it authenticates the ciphertext under the original package-hash owner and keeps that owner and local mappings. The package SHA-256 still binds grants and account tokens. A new device must recover the original Vault sync key through an explicit sync action; background page refresh never opens a password prompt.

See the [user guide](../../users/self-host-sync.en.md) for deployment and [`server/README.md`](../../../../example/self-host-sync/server/README.md) for the HTTP contract and single-instance restriction.
