# Self-hosted sync example

The complete source is in [`example/self-host-sync`](../../../../example/self-host-sync/readme.md): `plugin/` is a declarative Wasm plugin, `server/` is a single-user Go service, and `build-release.py` creates a companion Release ZIP. The new plugin declares `uiNavigation`, `uiPage`, protected `sshSync`, and minimum Core API 1.88. The host-owned secure flow reads login fields. Plugin code declares same-origin HTTP/HTTPS endpoints and sync actions but never receives Vault plaintext, the sync key, passwords, tokens, or exchange bytes. HTTP exposes passwords, tokens, and request metadata in transit.

From the repository root, run `PATH=<go-bin>:$PATH python3 example/self-host-sync/build-release.py`. This requires Go 1.23+, the locked Rust 1.97.1 toolchain, and its `wasm32-unknown-unknown` target. The script cross-builds six server binaries, exercises the real Wasm Plugin Host verifier and SDK `pack`/`check`, then creates separate server and plugin ZIPs. Building it does not install, authorize, accept on native desktop, or publish it.

The new plugin selects hosts, credentials and desktopProfiles, then coordinates HTTP GET/PUT, ETag/CAS, object conflicts and direction. Core supplies category-scoped, authorized snapshot/inspect/compose/apply/export/checkpoint operations; it owns encryption, Vault access, local commit and receipt-verified baseline updates. `networkStart` with `httpExchange` keeps encrypted request and response blobs in Core rather than Wasm. Separate Core read interfaces for preferences and terminal history exist, but this plugin does not use them. The legacy Core-owned Refresh/Sync and app scheduler are being replaced. Automatic sync policy and execution in the plugin remain implementation work; do not treat the earlier Core scheduler as the new contract. Older V4/V5 bundles must be authenticated before three-category V6 projection. The Go server retains its service password and strong ETag/CAS storage boundary.

Core derives a stable data owner from the plugin ID for new remote exchanges. For an existing exchange, it authenticates the ciphertext under the original package-hash owner and keeps that owner and local mappings. The package SHA-256 still binds grants and account tokens. A new device must recover the original Vault sync key through an explicit sync action; background page refresh never opens a password prompt.

See the [user guide](../../users/self-host-sync.en.md) for deployment and [`server/README.md`](../../../../example/self-host-sync/server/README.md) for the HTTP contract and single-instance restriction.
